# SFT NPU 适配与精度结果汇总

本文基于仓库提交记录整理 SFT 的 NPU 适配调整，精度数据引用 [inference_parser_fix.md](inference_parser_fix.md)。基础精度直接采用基础修复数据。下文精度指 SFT 模型在工具调用推理任务上的答案准确率，不是训练 loss 或 NPU 与 GPU 的算子数值误差。

## 一、SFT 的 NPU 适配调整

### 1. NPU 算子替换与依赖适配

主要对应提交：`dad6bf6`、`a1c3bff`、`ac608e1`。

- **精简 CUDA 相关依赖**：从 SFT 依赖清单移除 FlashAttention、FlashInfer、xFormers、Triton、Liger 等组件，并清理无关的图像处理依赖，使训练不再以这些 GPU 组件为安装前提。
- **RMSNorm 替换**：NPU 分支使用 `torch_npu.npu_rms_norm`，对输入执行连续化处理；其他设备保留对应实现。
- **SwiGLU 替换**：将 gate 与 up 投影结果按顺序拼接，调用 `torch_npu.npu_swiglu`，再执行 down 投影，保持 SiLU 门控计算语义。
- **Attention 替换**：NPU 分支使用 `torch_npu.npu_fusion_attention`，采用 BNSD 布局，保留 GQA 原始 KV head 数，避免在进入算子前重复扩展 KV。
- **注意力掩码适配**：将模型中“True／1 表示可见”的掩码转换为 NPU 算子中“True 表示屏蔽”的掩码；兼容二维 padding mask 与四维 visibility mask，并补齐广播维度、保证张量连续。

这些修改集中在 `training/sft/models/sdar/modeling_sdar.py`。`ac608e1` 的提交说明记录了模拟 NPU 接口的 CPU 算子契约测试及回归测试通过；该记录本身不构成原生 NPU 内核数值对齐或性能提升的证明。

### 2. 模型加载与训练计算兼容

主要对应提交：`a1c3bff`。

- **提前注册和检查设备**：在 Accelerator 初始化前导入 `torch_npu`，检查 NPU 是否可用，并核对 Accelerator 实际选择的设备，避免设备配置与实际运行不一致。NPU 路径不启用 CUDA TF32 设置。
- **检查模型完整加载**：先读取 SDAR 配置，再加载权重，通过 `output_loading_info=True` 检查加载异常，并核对模型层数与配置一致性。
- **兼容 safetensors 权重存储**：对未由 ZeRO-3 分片管理的参数，先复制到独立 CPU 存储，避免将文件映射的权重页直接传输到 NPU；已分片参数沿用 ZeRO-3 的存储管理。
- **调整反向计算路径**：关闭训练时 KV cache，使用非重入式梯度检查点；关闭融合交叉熵，保留训练代码基于 logits 自行计算损失的路径。
- **约束实际展开序列**：按 prompt、response 与 noisy response 展开后的实际输入长度检查可选长度上限，同时保持样本与监督信息对齐。完整训练配置可关闭该长度上限。

### 3. 多卡启动与优化器更新适配

主要对应提交：`a1c3bff`、`2093a03`、`9b554db`。

- **统一 NPU 启动入口**：通过 YAML 配置 Python 环境、CANN 路径、可见设备、进程数与通信端口；启动前加载 CANN 环境，设置 `DS_ACCELERATOR=npu`，通过 Accelerate 启动 DeepSpeed 训练。
- **支持八卡训练**：配置八个训练进程及 NPU 0–7，沿用 Accelerate + DeepSpeed ZeRO-3，结合 BF16、梯度累积与梯度检查点完成完整模型训练配置。
- **修正参数组兼容问题**：创建优化器前移除空参数组，避免 DeepSpeed 与学习率调度器持有的参数组数量不一致。
- **对齐真实参数更新边界**：学习率调度器仅在 DeepSpeed 实际完成优化器更新时推进，避免每个 microstep 都推进学习率而与梯度累积错位。
- **提供完整数据训练配置**：`9b554db` 新增完整 SDAR 模型、全量训练数据、八卡、3 个 epoch 的配置；提交时设置每卡 batch size 为 1、梯度累积为 16，对应有效全局 batch size 为 128。这里描述的是该提交的配置，不代表额外验证了实际训练完成情况。

## 二、三类修复的精度结果

### 统计口径

1. **基础修复（基础精度）**：恢复 T5Chem 源码、预测工具所需权重、PatentCheck 网络访问，以及放宽工具超时时限。直接采用来源文档推荐的基础修复数据。
2. **单边引号修复**：在基础修复之上增加 SMILES 边界引号兼容，对应来源文档的“基础修复＋引号修复”。`3503c71` 去除指定工具输入首尾多余引号，并要求处理后的 SMILES 通过 RDKit 验证；并非修改分子结构。
3. **所有修复**：采用最终 `combustion` 阶段结果，包含引号兼容、依赖及环境恢复、Query2CAS 的 SMILES 查询回退、燃烧分析命名参数适配等已纳入最终结果的处理。

基础修复与单边引号修复均为按样本组和已有判分拼接的**估算**，不是独立消融实测；所有修复为最终已有结果的判分统计。PatentCheck 相关提交提供的是续跑入口，网络恢复不能归因于该提交的代码修改。“所有修复”指最终阶段已实施的修复集合，不表示所有失败都已消除。
